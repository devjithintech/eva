Anatomy of one request

A single question fans across five actors and comes back as a typed view. Solid = forward, dashed = response. The figures are fetched server-side, and nothing executes until you approve.

The choreography slide — pair it with the event-stream slide: that one shows the wire events, this shows who talks to whom, in order. Two beats to land: (1) the data hop — the agent fetches real figures from your store, the model never sees them; (2) the dashed return path ends at you, and nothing executes until you approve. This is the security + trust answer drawn as a sequence.

The model picks a tool — the canvas renders the component

Eight render_* tools map one-to-one to typed React artifacts. The model only chooses which; the component owns the layout. Adding a view = one tool + one component.

The mechanism behind "generative UI," made concrete. The model's whole job on the UI side is choosing a tool name from a fixed set — it can't invent a layout or a number. Each tool resolves to one typed React component the design team owns. The growth story: a new view is one tool definition + one component, and the agent can use it immediately.
